# Brand assets

The identity lives in the website repository, **[hcekne/anaxigraph-website](https://github.com/hcekne/anaxigraph-website)**, not here. One home means the site, the dashboard and the package cannot drift apart the way they did before 0.7.2, when the dashboard and the README still shipped an August mark while anaxigraph.dev had moved to V4.

| What | Where |
|---|---|
| Canonical mark | `public/brand/anaxigraph-brand-v4-mark.svg` |
| Generated icons and horizontal logo | `public/brand/` |
| Browser icons, per theme and version | `public/brand/browser/<version>/<theme>/` |
| Typeface | `brand/fonts/` |
| Design explorations | `brand/source/explorations/` |
| Theme and version selection | `brand/site.json` |

Published assets are generated by `scripts/build-brand-assets.mjs` and `scripts/build-browser-icons.mjs` in that repository; `npm run assets:check` verifies them.

## What this repository ships

`src/anaxigraph/dashboard/favicon.svg` is a copy of the canonical mark, served by the dashboard at `/assets/favicon.svg`. The README points at that file through a commit-pinned raw URL, because PyPI renders the README from the published package and a moving reference would change the project page without a release.

**When the mark changes:** update it in the website repository first, copy the new `anaxigraph-brand-v4-mark.svg` over `src/anaxigraph/dashboard/favicon.svg`, then repin the README URL to the commit that carries it. The copy is deliberate — a build-time fetch would make packaging depend on a network request.
