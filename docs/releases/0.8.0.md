# AnaxiGraph 0.8.0

This is a release candidate. Publication is pending, and nothing below should be read as evidence
that the version is available or deployed.

AnaxiGraph now carries reusable architecture with your repository and turns that understanding
into an optional, agent-directed architecture plan. Mapping, Pattern analysis, Fresh Eyes and
Architecture planning connect the work, its progress and its results in one place. This release also addresses
development feedback about stalled reviews, oversized agent replies, worktree identity and unclear
comparison baselines.

## Workflows are the starting point

- Interactive diagrams show each stage's inputs, outputs, coverage, recorded models, reported
  tokens and results. Select a stage to configure its next provider, model, effort and workers.
- Run the full selected workflow, continue unfinished work, or update changed results. Completed
  workflows say they are up to date. Each card offers **Run this step** and explains its prerequisites;
  errors belong to the selected workflow and saved scan. Try two jobs before a large run.
  Saving settings alone makes no model calls. Optional analysis remains explicitly not run.
- Worker pools refill available slots continuously. Independent prerequisites can run concurrently,
  and progress distinguishes prepared work, active workers, reuse, retries and saved completion.
- Compact diagrams, step dialogs and responsive layouts make the controls usable on laptops and
  phones. Versioned asset URLs deliver frontend updates to browsers with cached assets.
- Host execution with uv is the recommended agent setup: the service can use installed,
  authenticated Codex and Claude CLIs under the same user account. Docker remains supported for
  serving the map to connected agents and host workers; it does not bundle those CLIs or logins.

The README and onboarding guide explain this path, updating the installed tool, and the shared
dashboard/agent coding loop. The agent receives your outcome, examples, taste and boundaries;
AnaxiGraph supplies ownership, dependencies, relevant tests and a comparison after editing.

## Architecture planning connects the findings

The fourth workflow combines the saved map with available Pattern and Fresh Eyes conclusions.
Direction is optional: leave it blank, choose a suggestion, or let the coding agent set the goal.
The agent compares preserving the current design with incremental evolution, chooses a target,
and records its rationale, assumptions, risks and evidence. A user can change the choice later.

Current and proposed architecture appear together, with added, moved, changed and retired
responsibilities. Structured diagrams and Mermaid exports keep the target accessible to agents
and readable in Git. Migration milestones name owners, affected contracts, dependencies, focused
verification and rollback. Agents can report verification evidence through the existing Guide
tool; selected targets and milestone history survive source changes without another planning run.

Fresh Eyes' initial proposals and adjudication remain implementation-blind. Its later comparison
uses Mapping and saved Pattern reviews; the workflow identifies which reviews were recorded and
whether newer evaluations are available.

## Bring the architecture home with a normal Git pull

Explicit workflow runs save a tracked root `anaxigraph/` folder. Its manifest and checksummed,
deterministic JSON/JSONL partitions carry the complete logical map, file understanding,
dependencies, findings, reviews, planning decisions and model provenance. Readable plan and
Mermaid files sit alongside those records. Active workers, leases and machine paths remain local.

SQLite remains the fast local query cache. Startup and source refresh import changed shared
records and verify the actual checkout before reusing compatible results. Artifact-only commits
do not invalidate their own map; unchanged saves produce no Git changes. Unknown formats,
corruption and unrelated existing folders fail explicitly, preserving the local index.

Use `anaxigraph refresh . --workflows mapping --json` in Flowthink or another scheduler. Request
Patterns, Fresh Eyes or Architecture planning independently, on their own cadence. Successful
work is checkpointed during a run and saved on exit; incomplete work remains incomplete and
returns a failing exit status. The scheduler's authorized Git commit/push publishes the folder;
AnaxiGraph itself does not schedule jobs or push your repository. A read-only service can load
shared records; saving requires write access to the reserved artifact directory.

## Reviews save useful work as they go

Mapping step 5 reviews independent batches in parallel within each configured pass, keeping
OpenAI and Claude passes ordered. Each completed batch is saved immediately. An interrupted run
reuses successful batches and retries failed work rather than repeating a complete pass. Progress
shows completed/total batches, active workers and elapsed time, followed by a labelled final
reconciliation phase that combines the findings into one reviewed map.

Pattern analysis repairs cached plans that point to retired assessment or review jobs. Step 3 can
continue through independent critiques and saved evaluations while retaining completed work.
Fresh Eyes has regression coverage across proposals, adjudication, comparison, mission filtering,
grounding, generations, provider assignments, retry and resume.

## Small replies and precise repository evidence

- Guidance and impact use an 8 KB default response budget, respect smaller configured budgets and
  report total/returned/omitted counts. Full evidence is available with `details=true` or CLI
  `--details`. MCP text no longer repeats the complete structured JSON response.
- Implementation guidance distinguishes source, tests, documentation, configuration and measurement
  artifacts. Adding benchmark JSON alone does not imply a regression or a need to inspect callers.
- Linked Git worktrees are discovered automatically and retain distinct checkout identities. Service
  selection verifies the checkout; a matching remote alone cannot select another clone's index.
- The dashboard identifies path, branch, indexed commit and current commit. Structural, AI mapping,
  Pattern and Fresh Eyes freshness are reported separately for the selected snapshot.
- File lists fetch all pages, label partial counts and search caps, and load full details on demand.
  Historical findings and AI status come from the selected snapshot.
- Reassessment pins an explicit baseline across implementation phases and displays snapshot IDs,
  commits, branch, paths, times and uncommitted-content identity.

## Responsiveness and evidence

Current views load independently of history and reassessment. Workflow polling reads compact
progress without loading retained Fresh Eyes proposals, generation history or evidence manifests.
Dashboard file pages omit full descriptions until opened.

The retained [usage benchmark](../../benchmarks/results/usage-feedback-2026-10-20.json) measures
a synthetic 1,000-file repository through the real HTTP application and SQLite index, without
model calls. Across ten trials, workflow polling took 69.51 ms median / 83.138 ms p95. Compact
250-file pages reduced response size from 1,065,388 to 496,320 bytes. The shared development host
had concurrent tests; these observations are not live-provider or production latency guarantees.

The [repository-record benchmark](../../benchmarks/results/repository-record-2026-10-21.json)
uses real Git and SQLite with synthetic source, without model calls. A 1,000-file record occupies
8.4 MB in 50 partitions: saving took 0.482 seconds, an unchanged save took 0.382 seconds with
zero changed files, and a clean clone loaded and verified all 1,000 files in 1.886 seconds with
zero structural reanalysis. The 120-file case occupies 1.0 MB and loaded in 0.450 seconds.

Automated Fresh Eyes coverage uses simulated executors, including subprocess fixtures. No new
live-model Fresh Eyes evaluation was performed for this release. Architecture recommendations
still require source inspection; fewer bugs, faster delivery and 10×/100× gains are not established.

## Compatibility and upgrade

The AnaxiIndex schema remains 11. No database migration is introduced. Saved review checkpoints
use the existing queue and document storage. Agent plugin manifests match version 0.8.0.

For a tool installation, run `uv tool upgrade anaxigraph`, then restart the service. For the
one-command setup, use `uvx --refresh anaxigraph up . --open --semantic agent --connect codex`.
Use `--connect claude` for Claude Code. Keep the existing external index and its adjacent
`.workflows` settings directory when moving a service.
