# AnaxiGraph 0.5.0

Release candidate — publication and production verification are still pending.

## Highlights

- Oversized Codex inputs use lossless temporary evidence pages, avoiding the CLI
  character limit. Fresh-eyes packets also select representative modules and
  boundary links and enforce an explicit serialized evidence budget.
- Failure modes have distinct score meanings and a `remediate` recommendation.
  AnaxiGraph no longer encourages adopting or strengthening a harmful structure;
  unsafe legacy advice is withheld from actionable views.
- Incremental status explains saved-document reuse. A prior Living Charter remains
  available as explicitly stale context while changed evidence is refreshed.
- Parent-scope pattern checks receive bounded child contracts, responsibility
  witnesses, boundary links, and source excerpts. The existing Work Queue card
  recognizes durable-queue and lease evidence without expanding the catalogue.
- Review goals persist through resume and reach the comparison and final review.
  A goal change reuses blind proposals and adjudication; raw goals are withheld from
  those stages because they can contain implementation details.
- A small model-backed judgment benchmark distinguishes justified existing designs,
  harmful structures, unnecessary changes, and genuinely insufficient evidence.

This release also includes the post-0.4.0 multi-model review work: selectable
generations and comparison, grounding checks, executor diversity and pins, declared
context, accurate usage provenance, guarded writes, and clearer operational errors.

## Compatibility and scope

Existing indexes remain readable. Upgrading from the published 0.4.0 release may
migrate the index to schema 11; back it up before replacing a running service.
Rollback must use the matching pre-upgrade index backup, not assume an older binary
can read a newer schema.

A missing relationship-set lookup index is installed before upgrade compaction and
restored when reopening an existing index. This avoids repeatedly scanning every
edge in a large retained history; backup and migration validation are unchanged.

`pattern-scores-v2` changes failure-mode interpretation and adds `remediate` to
recommendation filters. The explanation contract is `pattern-explanation-v3`.
Saved assessments are not rewritten: pattern work is revalidated under the new
contract. File-reading and contextual-description contracts are unchanged, so this
does not require rereading every unchanged source file.

`fresh-eyes --start --goal "…"` and the existing REST/MCP/dashboard workflow accept
an optional goal of at most 4,000 characters. Omission preserves the saved goal;
an explicit empty goal clears it. Evidence selection and compaction are disclosed
in saved manifests. Missing sampled evidence is never proof that code should be
deleted or that a pattern is absent.

No new runtime dependency, index table, public command family, normal MCP tool,
review stage, or automatically applied refactor is introduced.
