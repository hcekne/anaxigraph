# AnaxiGraph 0.5.1

Corrective release in preparation. Publication and successful production acceptance
are separate gates below; this record does not claim either has happened.

## Corrective scope

- [x] Remove the obsolete `file_versions` foreign keys from all three legacy
  semantic tables before compatibility compaction. Preserve canonical file facts,
  document identities, other constraints, and indexes inside the existing migration
  transaction. Refuse retirement when a module record lacks its canonical fact.
- [x] Repair the same obsolete constraints when opening an already-upgraded
  schema-11 index affected by 0.5.0. Skip that repair transaction on unaffected opens.
- [x] Detect missing foreign-key parent tables in migration validation and index
  health, including empty tables and NULL references that `foreign_key_check` misses.
- [x] Explicitly close backup and initialization connections. Produce standalone
  rollback-journal backups, restore closed legacy WAL backups from read-only storage,
  and reject a backup with a nonempty sidecar journal instead of silently ignoring it.
- [x] Install commit, pre-merge, and push hooks. Run the documented tests and coverage
  gates before push, check release/ledger/version consistency, compare publication
  with PyPI, and reject newly introduced merge history in CI. Local hooks do not
  replace server-side review or administrator enforcement.
- [x] Correct the 0.5.0 publication and failed-rollout record without pretending
  its approving-review and linear-history protections were satisfied.
- [x] Rehearse upgrade, restore, retained-data parity, and semantic writes against
  both the actual schema-10 backup and the failed schema-11 rollout backup.
- [ ] Pass full quality, browser, package, container, and protected PR checks.
- [ ] After a verified production upgrade, refresh changed semantics with GPT-6
  Astra/medium and finish the outstanding architecture review with GPT-6 Astra/max.
  Keep unchanged-scope reuse and snapshot provenance; a running worker is unfinished.

## Compatibility and evidence

This patch keeps schema version 11. Upgrades from the supported released schemas
still use a validated automatic backup and atomic migration. An index already
affected by 0.5.0 receives a targeted transactional constraint repair; it does not
need its immutable facts or AI descriptions regenerated. Back up before cutover,
and retain the matching old image and index for rollback.

The regression fixture reproduces the released inline foreign-key declarations,
not merely a fresh schema with its version number changed. Both schema-10 upgrade
and schema-11 repair now exercise saved-document reuse, scope upserts, job claiming,
submission, and document insertion after initialization. Dedicated recovery tests
retain connection references to prevent garbage collection from hiding leaks and
exercise read-only legacy backups and nonempty-journal refusal.

On 8 September, **36 focused migration/recovery/checkpoint tests** passed, as did
**42 combined hook, legacy-schema, and recovery regressions**. Whole-repository
lint, format, size, and architecture checks passed. The full release gates above
are separate and remain pending until their results are recorded.

Two private retained-index rehearsals passed restoration, canonical read parity,
semantic planning/reuse, job claiming, a synthetic test submission, and post-write
health. Synthetic probe descriptions stayed in disposable copies, never production:

- The schema-10 copy retained 2 repositories, 1,132 snapshots, 144,288 file facts,
  7,682 semantic documents, 6,105 semantic claims, and 540,337 coverage rows before
  the deliberate write probe. Restore took **21.259 s**, migration **30.006 s**,
  and the full rehearsal **103.802 s**.
- The failed-rollout schema-11 copy retained 2 repositories, 1,156 snapshots,
  146,351 file facts, 7,682 semantic documents, 7,041 semantic claims, and 540,922
  coverage rows before its probe. Restore took **20.381 s**, same-version repair
  **2.877 s**, and the full rehearsal **76.740 s**.
- Six sampled historical/current frames per copy had identical file, symbol, and
  relationship digests before and after repair. Both repositories' identities and
  current snapshots were unchanged. Full health passed with no missing FK parents
  or row violations and at most 15 traversed deltas. This is upgrade/write evidence,
  not a completed AI map or a claim that the production deployment has occurred.
