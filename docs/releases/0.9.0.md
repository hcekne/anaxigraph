# AnaxiGraph 0.9.0

This is a release candidate. It is not published to PyPI or deployed.

AnaxiGraph now centers its understanding on a typed semantic graph. One compact module annotation
replaces two file essays; functions, interfaces, caller contracts and relevant tests can be followed
through the dashboard and AnaxiMCP. Workflows remain the place to build and review that understanding.

## Read sentences, then follow behavior

- Modules expose one overview sentence and a short paragraph; functions receive individual behavior
  sentences. Named contracts retain inputs, outputs, failures, side effects and invariants without
  duplicating the same explanation in lookup rows.
- The shared inspector connects table rows and graph selections. Global sorting/filtering/paging,
  optional inventory columns, typed directed edges, evidence-state filtering, keyboard relationship
  lists and a back trail keep exploration focused. Structural readiness and annotation coverage differ.
- Observed code, the functional brief, Fresh Eyes alternatives and planning targets have separate
  graph subjects and revisions. Proposed designs carry no invented source locations or LOC counts.
- Unused-code checks report incomplete evidence by scope. A dynamic loader in one scope no longer
  silently disables other scopes; candidate and unassessed counts remain distinct.
- Concurrent graph, Guide and Impact reads keep a consistent selected map while another checkout
  or historical map is being inspected. Repeated cache switching returns a retryable error.
- `ANAXIGRAPH_GRAPH` pages sentences or expands relationships; `ANAXIGRAPH_ENTITY` reads the saved
  detail and obligations. FILE/SEARCH retain compact defaults and explicit full-detail reads.

## Consider the catalogue and preserve alternatives

Pattern analysis accounts for every loaded catalogue ID; the bundled catalogue contains 133 cards.
Each card gets contextual ratings, pros/cons, contrary evidence and useful placements, followed by
an independent critique. Considered, rated, reviewed, missing and unresolved counts remain distinct.
A completed insufficient-evidence review is visible as unresolved, not a clean endorsement.

Fresh Eyes prepares a product/capability/subsystem functional hierarchy and retains three alternatives
per reviewed scope, with five optional. Supplied contexts are implementation-blind; managed workers
run without tools. External worker isolation remains explicitly unverified. Child designs
refer to proposed parent constraints. Comparison examines decomposition, control flow, state ownership,
failure isolation and functional fit; converged designs and unexplored directions remain explicit.
Saved slots are not proof of different architectures, and novelty remains unverified.

Architecture Planning combines observed graph evidence, Pattern reviews and retained alternatives.
Direction can be blank; the agent can select a justified default. Users can choose another saved
option and inspect current/target diagrams, Mermaid, affected contracts and migration milestones.
Source-aware comparison belongs here, outside Fresh Eyes.

## Keep useful understanding, rebuild disposable indexes

Portable record v4 carries current semantics, contracts, selected analyses/plans, workflow choices and
provenance in `anaxigraph/`. New records use readable JSONL partitions; original legacy results stay
losslessly compressed and readable. Code-derived graphs, parser caches, runtime data, live queues
and credentials remain local. Imports validate source fingerprints before reusing compatible work
in a different clone or worktree.

The migration keeps original saved values and provenance behind a validated backup. It removes
copied claims/search content and obsolete writers rather than silently truncating saved analyses.
Current exclusions and byte/file limits apply before export; failed staging output is cleaned and
the last valid record survives. Unchanged scans/imports/exports and bounded retention are tested.
Legacy review reruns remain accessible even when their original generation metadata is incomplete;
that uncertainty is labelled rather than replaced with a new judgment.

Default storage policy shares 100,000,000 steady retained bytes, with a 25,000,000-byte / 32-file record ceiling
and a 95,000,000-byte local index ceiling competing for that pool. The configurable absolute ceiling
is 200,000,000 physical bytes. Index, shared memory and the portable copy share the retained pool;
WAL, journals, SQLite temporary files and staged copies also count toward the transient ceiling.
Compressed legacy data inside the index is counted once. Backup bytes and known migration peak are
reported separately. These policy values are not
a measurement of every migrated repository. Final same-dataset storage acceptance is recorded in
the [implementation audit](../design/semantic-graph-redesign-2026-10-23.md#implementation-and-acceptance-audit).
The [actual default-policy clone](../../benchmarks/results/semantic-graph-storage-2026-10-23.json)
uses **98,700,489 bytes** for its complete index and portable copy, imports all 5,872 saved documents
and parses 2,598 matching files without model calls. After an edit, planning and saved-baseline
restoration, the default-policy map used **99,110,089 bytes** with 2,597 current module analyses
and one queued annotation.
The existing index upgraded to **103,648,457 bytes** under its original user-configured
190 MB index / 200 MB total / 5 MB record policy, preserving all original saved documents.
That configured upgrade is not a claim that every legacy index fits the 100 MB default.
Cold source parse/import took 256.434 seconds under concurrent load; it does not measure new model
analysis. Recovery backup space is additional.

Normal scans keep compact per-path Git observations rather than an accumulating commit biography.
Counts and dates name their observed window; migration preserves exact known aggregates until the
Git HEAD changes. Explicit history/detailed-history choices keep the loaded commit rows.
Distribution version changes alone no longer invalidate structural caches; explicit analysis and
analyzer contracts still control reanalysis.

Mapped locally, record exported, Git committed and Git pushed are separate statuses. A scheduled
`anaxigraph refresh` saves partial progress; the scheduler owns Git publication. On the coding host,
a normal pull/import makes compatible saved understanding available without another model run.

## Upgrade and validation

The [final source CI run](https://github.com/hcekne/anaxigraph/actions/runs/40017458597)
passed all seven jobs, including 1,641 Python 3.12 tests, 114 browser contracts, all four
Linux/macOS package builds, coverage, the hardened container and the first-user journey.

For authenticated host workers, uv remains the recommended runtime:

```bash
uv tool upgrade anaxigraph
anaxigraph up . --open --semantic agent --connect codex
```

Stop the old service first and restart after updating. A uvx installation can restart with
`uvx --refresh anaxigraph up . --open --semantic agent --connect codex`. Preserve the existing index
and workflow settings. Docker users can continue using their container or follow the
[backed-up Docker-to-uv migration](../advanced-operations.md#persistent-host-dashboard-with-uv).
Older records load through compatibility readers; deliberately forcing Mapping enriches legacy
module descriptions with the new function/contract annotations.

The [frontend acceptance](../design/semantic-graph-frontend-2026-10-23.md#implementation-and-acceptance)
and backend audit link reproducible fixtures and focused regression suites. Recorded browser evidence
includes global 5,000-module pagination and all saved graph subjects. The
[first-user runtime check](../../benchmarks/results/first-user-annotation-2026-10-23.json) reached a
healthy dashboard in 2.951 seconds and submitted a one-function annotation in 3.253 seconds on a
synthetic fixture without model calls. The
[browser scale measurement](../../benchmarks/results/semantic-graph-browser-2026-10-23.json) uses
mocked backend data; it is not a production latency claim.

A [matched 62-file maintenance fixture](../../benchmarks/results/semantic-maintenance-2026-10-23.json)
compares 0.8.5 source with the candidate across five states. It exercises preserved provider behavior,
a deliberate contract break and the required companion migration. Function traversal excludes an
unrelated caller; the default baseline-state overview is 2,247 rather than 14,112 bytes. The small
fixture's local index grows from 823,296 to 2,048,000 bytes, so a richer graph is not automatically
smaller. Semantics are manually supplied and no model makes a design judgment in this test.

No new live model run demonstrates novel architecture discovery, fewer bugs or a seven-hour-to-fast
workflow speedup. Full catalogue accounting, blindness, saved alternatives and navigation are tested
protocol behaviors. The [retained feedback](../feedback/2026-10-23-architecture-and-storage.md) and
[research agenda](../graph-and-architecture-review-2026-10-23.md) remain part of the evaluation work.
