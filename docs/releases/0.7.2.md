# AnaxiGraph 0.7.2

This is a release candidate. Publication is pending, and nothing below should be read as evidence
that the version is available or deployed.

Most of a mapping run is one description per file, and until now every one of them ran on whatever
model the run was launched with. This release lets a repository say which model does which kind of
work, and lets two providers share the queue.

## Choosing a model per kind of work

A stage tier names a provider, model and reasoning effort for module, group, taxonomy or repository
work. The tier is read from the request the planner already builds, so no planner or worker protocol
changed. The executor belongs in a tier because which command-line tool runs is part of choosing a
model: a run launched against Codex cannot otherwise reach a Claude model.

A tier that names nothing leaves the claiming pool alone, and that is the point. Two pools read the
same code a little differently, and two pools of sixteen stay inside each provider's rate limit
where one pool of thirty-two would not. `--stage-model` sets a tier for one run without editing the
policy, because the cost is felt at the run.

What actually ran travels with the result. A staged run claims with the run default and may execute
on another model, and on another tool entirely, so recording the claim would have named the wrong
author on every synthesis.

## A findings ledger that can be read

A repository with 61,636 findings took over a minute to return a page of five. Ranking wrote the
reader-facing prose for every row before anything was filtered or paged, and threw almost all of it
away. Score, reasons and actionability are still computed for every row, because ranking, the
architecture-area filter and diagnostic grouping all read them. Only the prose moved, and it is now
written for the returned page before the byte budget is measured, so budgets and cursors are
unchanged. Measured on 61,636 synthetic findings: 29.7 seconds to 1.6. The live figure is not
claimed here, because the running service is an older build.

## Saying what did not run

Detailed pattern review is off by default. Status reported that stage as ready, concluded the map
was up to date, and left the stage out of compact status, so a reader saw full coverage, no pattern
findings and no reason why. Readiness is now reported only for work that was eligible. The internal
gate is unchanged: a disabled stage still does not block `baseline_complete`, which is a different
question that happened to share an answer.

## One identity

The dashboard and the README shipped an August mark while anaxigraph.dev had moved to V4, so the
PyPI project page showed the old art. All three now carry the same mark, and `docs/brand.md` records
that the identity lives in the website repository along with what to do when it changes.

## Compatibility

The AnaxiIndex schema remains 11. No new dependency, endpoint, service or migration. Saved semantic
work is untouched: stage tiers change which model is asked, not what a saved document means.
`ANAXIGRAPH_SEMANTIC_SUBMIT` accepts optional executor fields; a caller that omits them behaves
exactly as before.

## Known and not fixed here

- The worker executes in batches, so a slow member delays the next batch rather than each free slot
  refilling continuously. With two providers of differing latency the faster pool will idle.
- Chunked and reduced analyses do not carry cache counters or the usage-reported flag forward, so
  their totals record as unknown usage. Those zeros are not free execution.
