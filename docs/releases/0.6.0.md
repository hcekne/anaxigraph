# AnaxiGraph 0.6.0

This release makes routine semantic mapping concise and lets background software manage long
runs without repeated supervision by the calling model. Publication and production acceptance
are pending; the checklist below records them separately.

## Changes

- Routine file descriptions use five fields: summary, responsibilities, essential caller-visible
  behavior, evidence, and confidence. Short English replaces the mandatory detailed review on
  every file. Detailed refactoring, pattern, and understandability reviews are opt-in through
  `semantic.detailed_reviews: true`; saved historical reviews remain available.
- A 100–200-word writing target allows extra essential behavior for complex files. Field lengths
  and item counts do not reject or silently truncate that behavior. Confirmed output truncation
  receives one retry per attempt with more headroom, preserving both calls' reported usage.
  Defaults are 4,000 output tokens initially and an 8,000-token retry ceiling, configured with
  `max_output_tokens` and `max_output_tokens_on_retry`. Aggregate usage can exceed a per-call limit
  across chunks, attempts, and calls inside an executor CLI.
- Prompts put shared instructions before file content, and intermediate descriptions avoid
  repeatedly carrying full reviews. Routine MCP schema reads return only the requested artifact.
- Background launches reuse active run handles and join prepared queues. Preparation contention
  is waited out with backoff; startup reports a clear error after ten minutes of contention.
  Existing parallel execution remains available across executors under the shared repository
  limit, including 32 and 48 concurrent jobs.
- MCP status defaults to compact progress; CLI and REST offer `--compact` and `compact=true`.
  MCP, the packaged agent skill, and onboarding direct callers to choose an economical worker
  model explicitly, return the run handle, and avoid supervisor scripts, process-name checks,
  and frequent LLM polling. Status is read on request or normally after at least five minutes.
- Optional understandability assessments identify concrete maintenance tasks, the source of
  knowledge needed for them, obstacles, and small verifiable improvements. Guidance, reassessment,
  and file views distinguish inferred assessments from measured reader performance. The goal is
  code that readers can navigate and modify using the repository itself.
- Preserve the absolute, immutable README logo URL shipped in 0.5.2 and its publication record.

## Compatibility

The AnaxiIndex schema remains 11. Existing facts, descriptions, and history are retained. The
new mapping contract refreshes affected descriptions when mapping is next prepared; deploying a
version is not evidence that the semantic map or any architecture review has finished.

MCP consumers needing the previous full status must pass `details=true`. Consumers inspecting
every result schema must pass `artifact="all"`; a claimed task supplies its exact
`response_contract.schema_arguments`. Model, executor, and reasoning effort remain runtime
provenance rather than reasons to invalidate unchanged descriptions.

This release improves **Understand** and **Guide** using existing services and endpoints. It
replaces the mandatory rich per-file report and ambiguous monitoring instructions. The exact
production-source budget moves from 63,585 to 64,297 lines, a net increase of 712 lines across
the combined understandability and mapping changes. The callable-surface report is +12 / -6,
including six existing signature updates. Two semantic settings and optional arguments extend
existing surfaces; there is no new runtime service, endpoint, MCP tool, or database table.
