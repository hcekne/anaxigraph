# AnaxiGraph 0.8.4

This is a release candidate. It is not published to PyPI or deployed.

Portable architecture now carries current understanding rather than historical SQL caches. This
repairs a reported 3.22 GB failed export that included previously indexed runtime data excluded by
today's mapping policy. Git preserves previous maps; each server builds its own fast local index.

## Current understanding, bounded storage

- Record v2 carries concise file descriptions, architecture, selected reviews/plans, provenance
  and workflow choices. Code graphs, symbols, metrics, findings and historical SQL rows are rebuilt
  locally rather than transferred through Git. Unfinished queue payloads and live workers stay local.
- Export applies current exclusions and checks byte/file limits before writing. Failed writes
  clean new output and retain the last valid record. Sorted bounded partitions replace recursive
  hash subdivision. Successful saves remove old managed partitions.
- Defaults allocate 100 MB of active state, including a 25 MB / 32-file portable record and a
  64 MB local index. Configured totals cannot exceed 200 MB. SQLite page limits reject oversized
  writes and roll them back; write-ahead logs are checked before admitting more analysis.
- Local graph history keeps the current checkout and two comparison checkpoints. Selected latest
  reviews/plans and reusable descriptions survive separately without retaining their old graphs. Comparison
  lineage stays usable; an unavailable historical graph is reported explicitly.
- Historical mapping is opt-in through an explicit CLI option, registry choice or dashboard
  import. Existing explicit history choices are respected. Detached workers retain four recent
  runs per executor and bound their logs to 1 MB.

## Reuse paid understanding

Fresh clones rebuild code-derived indexes and validate file/analyzer fingerprints before reusing
AI descriptions. A source edit cannot import an obsolete description as current. Ordinary scans
retain compatible partial file understanding; unchanged scans/imports/exports do not accumulate
history. Output brevity changes preserve the 0.8.3 input-cache identity, avoiding a forced full AI run.

Default file descriptions target 40–100 words, with a 600-character summary and bounded lists.
Legacy descriptions are condensed for portability; original saved understanding is recoverable.
Review batch identities use candidate content instead of local document IDs, so completed work
survives movement to another index namespace. Repository scope keys and document links are rebound.

## Migrate an existing index

On the server owning the index, stop ongoing work and change an old automatic-history startup
setting to zero when history is not wanted. Then run:

```bash
anaxigraph record compact /path/to/repository --db /path/to/anaxi-index.db --json
```

Compaction first creates a validated recovery index containing saved AI results and provenance,
with rebuildable historical graphs omitted. That copy is limited to 64 MB and reserved against
the hard ceiling. It leaves the original intact if recovery data cannot fit. Compaction retains
saved analyses, shortens legacy descriptions unless detailed reviews were requested, prunes
disposable cache history, reclaims SQLite disk space and exports the current record.

The recovery index works with `anaxigraph restore`; a normal scan rebuilds graphs and reuses
compatible file analyses. Its path and actual storage sizes are reported. Retire the copy after
verifying migration. For shared indexes, compact each registered checkout against the same database.
An index whose saved understanding still exceeds its budget is reported as over budget and new
analysis is refused; selected results are not silently discarded.

Local mapping, exported records and Git commit/push are separate facts. AnaxiGraph does not claim
publication when it saves files; the authorized scheduler or agent commits/pushes the record.

## Validation and release ledger

Acceptance exercises real SQLite transactions, interrupted publication, a Git save/clone/import
round trip, complete and partial AI reuse, a resumed review batch in another repository/index
namespace, excluded historical runtime entries, bounded unchanged scans, recovery/restore and a
real detached worker emitting an oversized log. AI lifecycle checks use deterministic model fixtures.
The application-source storage measurement uses a temporary checkout; no production service was
restarted and no live model-quality claim is made.

The release ledger now commits publication evidence directly to main, following repository rules;
it no longer depends on an unavailable GitHub auto-merge configuration.
